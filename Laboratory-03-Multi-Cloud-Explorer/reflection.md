# Mission Reflection

The cloud platform that impressed me the most was AWS because of its broad range of services and the number of different workloads it can support. While AWS stood out to me, I also learned that Azure and Google Cloud have important strengths that can make them better choices for particular organizations. Azure is especially useful for organizations that already depend heavily on Microsoft technologies, while Google Cloud is very attractive for artificial intelligence, machine learning, data, and Kubernetes workloads.

AWS, Azure, and GCP have many similarities. All three provide compute, storage, networking, identity and access management, databases, monitoring, security, and managed application services. They also use global infrastructure and provide web-based management consoles. Although their service names and implementations differ, the basic cloud concepts are similar.

Business requirements strongly influence cloud platform selection. A company should consider its existing technology, budget, performance requirements, security needs, location of users, scalability, staff skills, and future plans instead of choosing a provider only because it is popular. For example, the university in this mission is better matched with Azure because it already uses Microsoft technologies.

Acting as a Cloud Solutions Consultant taught me to connect technical services with actual business needs. I learned that there is not always one cloud provider that is best for every situation. The best recommendation depends on the problem that the client needs to solve.

My GitHub Cloud Computing Portfolio also improved because I organized research, comparisons, recommendations, and screenshots into separate Markdown files. This makes the portfolio easier to understand and demonstrates my ability to document technical work professionally.
